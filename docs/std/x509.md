# std::crypto::x509

TLS server が示す証明書を読み、それが名乗る host を保証するかを決めます。
証明書は DER(RFC 5280)のまま読み、`Certificate` はその bytes への span を
持つだけで copy しません。理解する鍵と署名は `std::crypto` が持つもの ——
P-256 の鍵と ECDSA + SHA-256、RSA の鍵と PKCS #1 v1.5 + SHA-256 / 384 / 512 ——
で、他の種類は推測せず `Unsupported` と言います。

```text
std::crypto::x509::parse(der: []u8) -> Error!Certificate
std::crypto::x509::verify_chain(chain: &Array<String>, roots: &Array<String>, host: []u8, now: i64) -> Error!void

Certificate.subject() -> []u8        // subject Name の DER 全体
Certificate.issuer() -> []u8         // issuer Name の DER 全体
Certificate.serial() -> []u8         // serial number の bytes(big-endian)
Certificate.public_key() -> []u8     // P-256 なら非圧縮 point 65 byte、RSA なら RSAPublicKey の DER
Certificate.valid_at(unix_seconds: i64) -> bool
Certificate.matches_host(host: []u8) -> bool
Certificate.issued_by(issuer: &Certificate) -> bool
Certificate.not_before, .not_after: i64        // 1970 からの秒、両端を含む
Certificate.key_algorithm: KeyAlgorithm         // EcdsaP256 | Rsa | Unsupported
Certificate.signature_algorithm: SignatureAlgorithm   // EcdsaSha256 | RsaSha256 | RsaSha384 | RsaSha512 | Unsupported

std::crypto::x509::ecdsa_signature_verifies(public_key: []u8, digest: []u8, signature: []u8) -> bool
std::crypto::x509::rsa_pss_signature_verifies(hash: Hash, public_key: []u8, digest: []u8, signature: []u8) -> bool
Certificate.is_ca: bool                         // basicConstraints の cA

std::crypto::x509::Error   Malformed | Unsupported | Expired | NameMismatch | BadSignature | UnknownIssuer
```

```kizu
// chain: server が送った DER の列(host の証明書が先頭、次がその発行者、…)
// roots: program が信頼する root の DER
try x509::verify_chain(&chain, &roots, "www.example.com", now);
```

## verify_chain が確かめること

先頭の証明書が host を名乗ること、各証明書が `now` に有効で次の証明書に署名
されていること、そしてどれかが信頼する root に署名されている(または root
そのものである)ことです。最初に破れたところが答えで、`Expired`、
`NameMismatch`、`BadSignature`、`UnknownIssuer` のどれかです。順に見るので、
host を名乗らない期限切れの証明書は `Expired` です。

`now` は呼び手が渡します(`std::time::unix(process::unix_millis())` の秒)。
`std::crypto` と同じく、ここに時計はありません。

## 証明書が言うこと

`parse` は 1 枚の DER を読みます。読むのは RFC 5280 の TBSCertificate の各
field、SubjectPublicKeyInfo、拡張のうち basicConstraints と subjectAltName
です。keyUsage と extendedKeyUsage は critical でも読み飛ばし、それ以外の
critical な拡張は `Unsupported` です(RFC 5280 §4.2 は知らない critical 拡張を
持つ証明書を拒否するよう求めます)。

`matches_host` は subjectAltName の dNSName だけを見ます(subject の CN は
見ません)。比較は ASCII の大文字小文字を畳み、`*.example.com` は wildcard の
位置に 1 label だけ合います(RFC 6125 §6.4.3)。subjectAltName の無い証明書は
どの host も名乗りません。

`issued_by` は、`issuer` が証明書に署名してよく(`is_ca`)、その subject が
この証明書の issuer と同じ bytes で、この証明書の署名が `issuer` の鍵で検証
できることです。ECDSA の署名は `SEQUENCE { r INTEGER, s INTEGER }` から取り出して
`std::crypto::ecdsa_p256_verify` に、RSA の署名はそのまま `std::crypto::rsa_pkcs1_verify`
に渡し、証明書の signatureAlgorithm が言う hash を使います。鍵の種類と署名の種類が
合わなければ false です。

`ecdsa_signature_verifies` と `rsa_pss_signature_verifies` は TLS の CertificateVerify の
ためのもので、`public_key()` の bytes と digest と署名から、DER の中身の読み方だけを
ここが持ち、判断は `std::crypto` がします。

## 今は話さないこと

- P-384 の鍵と署名。公開 CA の chain にはまだ多い
- RSASSA-PSS で署名された証明書(署名は `Unsupported`)
- nameConstraints、certificatePolicies などの critical 拡張(`Unsupported`)
- 失効(CRL / OCSP)
- system の trust store の読み込み。root は呼び手が DER で渡します
